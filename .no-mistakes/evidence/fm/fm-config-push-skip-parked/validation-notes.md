# Parked secondmate validation

Acceptance oracle: the supplied author intent and subsequent recorded R1/R2/R6/R7 decisions. A proven watcher park suppresses reread notices while files converge; absent/doubtful park proof must preserve reread delivery, successful launches rearm, failed rearming must not silence a running agent, and launch must preserve already queued steers.

The real CLI was exercised using a disposable snapshot of target commit 0e04f6a5f4919142e0dcde453449bc6d52db626a. That snapshot was initialized as its own local Git repository, because remote command dispatch validates tracked executables. All snapshot code, fixture homes, SSH keys, dependency files and state were inside the gate worktree. Original tracked files were left unchanged. Private tmux sessions used a 120-column, 40-row grid. The existing Codex login was used; `--no-daemon` avoided changing the operator's shared daemon settings. No Herdr session or fleet pane was changed.

`live-local.log` records actual watcher parking, repeated config push, bootstrap convergence, a running Codex process with a stale marker, and a public `fm-control exit` preserving work before the next push. `live-spawn.log` records actual successful spawn/rearm, preservation of a preexisting queued steer, and actual launch with deliberately unwritable rearm bookkeeping followed by both convergence commands.

`live-remote.log` records the actual SSH client connecting to an ephemeral localhost SSH server with disposable keys. The server executed the unmodified real remote entrypoint, remote job worker, state consumer and inheritance receiver. No product script or returned state was mocked. An absent endpoint record let the real remote state command prove `missing` without addressing any Herdr session. An invalid endpoint record supplied the uncertainty counterexample. The watcher generated its own park record after the seeded prior attempt budget was exhausted.

Targeted automated checks also exercised remote relaunch/propagation concurrency and SSH-255-successful-launch conditions through their existing SSH-boundary fixtures. Those automated cases are not labelled live. A real successful remote relaunch requires the product's fixed `fm-remote` Herdr session, whereas the trusted gate runbook authorizes only `fm-lab-*` sessions operated through `fm-herdr-lab.sh`; this prevents a faithful live remote relaunch race here. No production session was used as a workaround.

Setup corrections: temporary fixtures beneath the source root hit the product's home-nesting guard, so tests were run from a sibling disposable source snapshot. The snapshot also needed Git tracking for remote dispatch. The first Codex instance presented a shared-daemon compatibility menu; subsequent live control used the documented `--no-daemon` flag. Spawn creates read-only hook directories, so fixture removal restored directory write permissions before deleting them. The SSH fixture initially closed its transport prematurely; it now waits for peer disconnection after publishing channel exit status. Private process-event state and claim roots are confined to the fixture.

Research used for fixture mechanics: [Linux Unix-domain socket pathname limits](https://man7.org/linux/man-pages/man7/unix.7.html), [tmux custom sockets](https://github.com/tmux/tmux/wiki/Advanced-Use), and [Paramiko channel EOF/exit-status/close API](https://docs.paramiko.org/en/stable/api/channel.html). These concern the disposable test harness, not product acceptance criteria. A fleet research book was not updated because the supplied workspace boundary forbids modifying the operator home or another checkout.
